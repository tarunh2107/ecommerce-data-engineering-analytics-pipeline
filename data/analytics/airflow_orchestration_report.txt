5. PIPELINE IDEMPOTENCY & FAULT-TOLERANCE DESIGN
================================================================================
Rather than relying on continuous runtime recomputation, pipeline idempotency is
guaranteed by architectural design across every layer of the system:

1. Raw Ingestion Layer:
   - Source CSV files in data/raw/ are strictly read-only.
   - Validators verify file existence, schema, and checksums without modifying inputs.

2. PySpark Clean & Transformation Layer:
   - In clean_data.py and build_star_schema.py, target directories are pruned via
     shutil.rmtree prior to writing, and DataFrames write with mode("overwrite").
   - This eliminates partial partitions, temporary files, or directory locking issues.

3. Data Warehouse Loading Layer:
   - postgres_loader.py executes a controlled TRUNCATE TABLE ... CASCADE within an
     atomic database transaction before COPY streaming begins.
   - Foreign key checks and unique constraints (customer_id, product_id, seller_id,
     order_id, uq_order_item) physically reject duplicate or orphaned records.
   - In Phase 4 verification, an automated full TRUNCATE & RELOAD test was executed
     and confirmed:
       * Initial Load: 349,405 rows
       * Post-Reload: 349,405 rows (Exact 0 difference, 0 duplicate keys)

4. SQL Analytics Layer:
   - All 7 analytical scripts query PostgreSQL views/tables deterministically.
   - Outputs written to data/analytics/sql_results/ use standard pandas to_csv()
     with index=False, cleanly overwriting previous outputs without duplication.
