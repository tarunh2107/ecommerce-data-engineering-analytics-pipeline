1. DASHBOARD ARCHITECTURE & MODULAR STRUCTURE
================================================================================
The web presentation layer follows a modular design pattern:

File / Module               Role & Responsibilities
-------------------------   ----------------------------------------------------
dashboard/app.py            Main application, wide-layout config, 7-page routing
dashboard/database.py       SQLAlchemy connection pool, .env loader, health check
dashboard/queries.py        11 cached analytical SQL queries with in-DB aggregation
dashboard/components.py     Custom CSS card components and Plotly chart builders

Database Connection Architecture:
  - Engine: SQLAlchemy 2.0 with psycopg2-binary driver.
  - Connection Pool: pool_size=5, max_overflow=10, pool_pre_ping=True, pool_recycle=3600.
  - Host Resolution: Strictly targeted to 127.0.0.1:5432 (bypassing Windows localhost IPv6 issues).
  - Credentials: Dynamically loaded from project root .env file.
  - Zero Hardcoding: No database passwords or sensitive host strings are committed.
  - Graceful Fallback: Built-in health check displays actionable recovery guidance if DB is down.

Query & Caching Strategy:
  - Push-Down Aggregations: All SUM, COUNT, AVG, GROUP BY, and window functions (NTILE, LAG, ROW_NUMBER)
    execute inside PostgreSQL. Zero large raw tables (e.g. 112K fact rows) are loaded into browser memory.
  - Caching Decorator: Every query is decorated with @st.cache_data(ttl=3600) to ensure sub-second
    client-side responsiveness and zero redundant database hits during widget interaction.

5. PROBLEMS ENCOUNTERED & RESOLUTIONS
================================================================================
1. Problem: Self-signed SSL certificate verification failure during pip install of streamlit and plotly.
   Resolution: Installed with explicit trusted host parameters:
   --trusted-host pypi.org --trusted-host files.pythonhosted.org --trusted-host pypi.python.org.

2. Problem: Missing 'Tuple' import from typing in dashboard/queries.py.
   Resolution: Added 'Tuple' to typing imports at top of module.

3. Problem: RFM unique customer count discrepancy (96,096 total vs 93,358 in RFM cohort).
   Resolution: Confirmed that 96,096 represents total unique customer entities across all order statuses,
   while 93,358 represents customer entities with fulfilled/delivered orders. Reconciled accurately.

4. Problem: ModuleNotFoundError: No module named 'dashboard' when running streamlit run dashboard/app.py.
   Resolution: Streamlit prepends the script directory (dashboard/) to sys.path rather than the project root.
   Resolved by inserting PROJECT_ROOT into sys.path at the top of dashboard/app.py and dashboard/queries.py,
   with resilient try/except fallbacks for both package-level and local imports.

5. Problem: Port 8501 conflict with concurrent Customer Churn project.
   Resolution: Reconfigured and launched the E-Commerce Analytics Platform on dedicated port 8502:
   streamlit run dashboard/app.py --server.port 8502, leaving port 8501 completely unaffected.

6. Problem: Extreme early-period MoM growth percentage outliers (+32,307% in 2016-10 and +649,657% in 2017-01)
   caused by near-zero prior revenue bases (< R$ 150 from 1 pilot order each) compressed the Y-axis, rendering
   normal monthly movements unreadable.
   Resolution: Preserved the exact SQL query and raw values in data models and detail tables. Refined the MoM
   line visualization to plot established operational periods (prior GMV >= R$ 1,000), allowing the Y-axis to
   dynamically scale to [-100%, +115%]. Early ramp-up outliers are explicitly annotated on the chart and
   fully documented in user-facing captions without capping or falsifying underlying data.
